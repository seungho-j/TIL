### Context
사용자가 n8n AI Agent를 사용하여 영어 입력을 처리할 때 원하는 출력 형식으로 결과를 얻는 데 어려움을 겪고 있으며, 주로 사용되는 모델인 `models/gemini-2.5-flash-lite`의 낮은 사양이 원인인지에 대한 의문을 제기합니다.

### Core
*   **모델 성능과 출력 형식**
    *   `gemini-2.5-flash-lite`는 속도와 비용 효율성에 최적화된 모델로, 복잡한 추론이나 정교한 형식 지시(formatting instructions)를 따르는 능력은 `gemini-1.5-pro`와 같은 상위 모델에 비해 제한적일 수 있습니다. 이는 "Flash" 모델이 "Pro" 모델보다 복잡한 명령 이해 및 실행 능력에서 차이가 날 수 있음을 의미합니다.
    *   하지만 출력 형식 문제는 단순히 모델 사양만의 문제는 아니며, 프롬프트 엔지니어링(Prompt Engineering)을 통해 상당 부분 개선할 수 있습니다.
*   **n8n AI Agent 출력 형식 최적화 전략**
    *   **명확하고 구체적인 지시 (Clear and Specific Instructions)**: 출력 형식을 프롬프트 내에서 명확하게 지정해야 합니다. 예를 들어, "다음 정보를 JSON 형식으로 출력하세요. 스키마는 다음과 같습니다: `{ "title": "...", "description": "..." }`"와 같이 구체적으로 지시해야 합니다.
    *   **Few-shot 학습 (Few-shot Learning)**: 원하는 입력-출력 쌍의 예시를 프롬프트에 직접 제공하여 모델이 특정 형식에 맞춰 응답하도록 유도할 수 있습니다.
    *   **출력 파서 및 유효성 검사 (Output Parsers and Validation)**: n8n 워크플로우 내에서 LLM의 출력을 받은 후, 추가적인 노드(예: `Code` 노드, `JSON` 노드)를 사용하여 원하는 형식으로 파싱(Parsing)하거나 유효성을 검사하고 재구성할 수 있습니다. LLM이 완벽한 출력을 제공하지 못하더라도 n8n의 후처리(post-processing) 기능을 활용하여 해결할 수 있습니다.
    *   **점진적 프롬프트 개선 (Iterative Prompt Refinement)**: 다양한 프롬프트와 모델 설정을 테스트하며 최적의 결과를 얻을 때까지 반복적으로 개선하는 과정이 필요합니다.
    *   **적절한 모델 선택 (Appropriate Model Selection)**: 복잡한 형식 지정 및 높은 정확도가 요구되는 경우에는 `gemini-1.5-pro`와 같이 더 강력한 모델을 고려하는 것이 효과적일 수 있습니다.
*   **코드 스니펫 (예시 프롬프트)**
    ```
    You are a technical document assistant. Your task is to extract key information from the user's input and present it in a structured JSON format.

    Input: The user wants to know about the new feature, "Dark Mode". It improves user experience by reducing eye strain in low-light environments.
    Output Schema:
    {
      "feature_name": "[Extracted Feature Name]",
      "description": "[Extracted Description]",
      "benefit": "[Extracted Benefit]"
    }

    Strictly adhere to the provided JSON schema for your output.
    ```

### Insight
n8n AI Agent가 원하는 형식으로 출력을 잘 못하는 문제는 `gemini-2.5-flash-lite` 모델의 낮은 사양 때문일 수도 있지만, 근본적으로는 **프롬프트 엔지니어링의 정교함이 부족**할 가능성이 큽니다. `gemini-2.5-flash-lite`는 빠른 응답과 저비용에 강점이 있으나, 복잡하고 엄격한 형식 지시를 정확히 따르는 데에는 `gemini-1.5-pro`와 같은 더 강력한 모델이 유리할 수 있습니다. 모델의 한계를 극복하기 위해 **명확한 지시, 예시 제공, n8n 내 출력 후처리(Post-processing)** 등의 전략을 병행하는 것이 중요합니다. 특히, LLM의 출력을 그대로 신뢰하기보다는 n8n의 다른 노드를 활용하여 형식을 강제하거나 검증하는 것이 필수적입니다.
