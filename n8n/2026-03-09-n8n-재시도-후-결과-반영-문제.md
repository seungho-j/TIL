### Context
n8n 워크플로우 테스트 중 발생한 에러에도 불구하고, 재시도 로직으로 인해 최종적으로는 성공한 결과가 반영되는 현상을 경험했습니다. 이는 n8n의 자체적인 재처리 로직과 관련된 문제로 보이며, 구글 AI 모델 자체의 문제는 아닌 것으로 판단됩니다.

### Core
n8n 워크플로우에서 에러 발생 시 재시도(retry) 설정을 활성화하면, 실패한 노드 실행을 몇 차례 더 시도합니다. 재시도 횟수 내에 성공하면 해당 결과를 최종 결과로 간주하게 됩니다. 이는 에러 발생 시 즉각적인 실패 처리가 아닌, 일시적인 문제 해결 후 성공적인 결과를 기록하도록 하는 n8n의 기본 동작 방식입니다.

```javascript
// n8n 노드 설정 예시 (Error Handling 탭)
{
  // ... other node settings
  "retryOnFail": true,
  "maxRetries": 3,
  "delayBetweenRetries": 1000 // milliseconds
}
```

### Insight
n8n의 재시도 기능은 일시적인 네트워크 불안정이나 외부 API의 순간적인 응답 지연과 같은 간헐적인 문제를 극복하는 데 유용합니다. 하지만 이 기능으로 인해 실제로는 에러가 발생했음에도 불구하고 성공한 것처럼 결과가 기록될 수 있습니다. 따라서 워크플로우의 정확한 실패/성공 여부를 판단하기 위해서는 단순히 최종 결과만 볼 것이 아니라, 각 노드의 실행 기록과 재시도 횟수 등을 함께 검토해야 합니다. 이 문제는 구글 AI 모델의 답변 생성 로직과는 별개로, n8n의 워크플로우 실행 및 에러 처리 메커니즘에 기인한 것으로 보입니다.
