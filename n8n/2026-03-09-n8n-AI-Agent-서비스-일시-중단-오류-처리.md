### Context
n8n 워크플로우 내 'AI Agent' 노드에서 "Service unavailable - try again later or consider setting this node to retry automatically (in the node settings)" 오류가 발생했습니다. 이는 외부 AI 서비스가 일시적으로 응답하지 않거나 과부하 상태일 때 자주 발생하는 문제입니다. 이러한 transient error(일시적 오류)를 효과적으로 처리하고 워크플로우의 안정성을 높이기 위해 n8n 노드의 재시도(Retry) 설정 방법을 이해하고 적용하는 것이 중요합니다.

### Core
n8n 노드에서 발생하는 일시적인 'Service unavailable' 오류를 처리하기 위해 'Retry On Fail' 설정을 활용할 수 있습니다. 이 기능은 특정 노드에서 오류가 발생했을 때 지정된 횟수만큼 작업을 자동으로 재시도하도록 구성합니다.

*   **재시도 설정 활성화**:
    1.  오류가 발생한 'AI Agent' 노드를 선택합니다.
    2.  노드 설정 패널에서 'Settings' 탭을 클릭합니다.
    3.  'Error Handling' 섹션 아래의 'Retry On Fail' 옵션을 찾아 활성화(토글 온)합니다.

*   **재시도 매개변수 구성**:
    *   **Max Retries (최대 재시도 횟수)**: 노드가 실패하기 전까지 시도할 최대 재시도 횟수를 지정합니다. 기본값은 3이며, 일시적 오류의 특성을 고려하여 적절한 횟수를 설정합니다.
    *   **Retry Interval (재시도 간격)**: 각 재시도 사이에 대기할 시간을 밀리초(ms) 단위로 지정합니다. 너무 짧은 간격은 서비스에 추가 부담을 줄 수 있으므로 주의해야 합니다.
    *   **Backoff Strategy (백오프 전략)**:
        *   **None (없음)**: 매 재시도마다 동일한 재시도 간격을 유지합니다.
        *   **Linear (선형)**: 재시도 간격이 선형적으로 증가합니다 (예: 1초, 2초, 3초...).
        *   **Exponential (지수)**: 재시도 간격이 지수적으로 증가합니다 (예: 1초, 2초, 4초, 8초...). 이는 외부 서비스의 과부하를 줄이고 시스템이 복구될 시간을 벌어주므로 외부 API 호출에 가장 권장되는 전략입니다.

*   **예시**:
    'AI Agent' 노드가 응답하지 않을 경우, 최대 5번까지 재시도하고, 재시도 간격은 지수적으로 증가하도록 설정할 수 있습니다. 이는 외부 AI 서비스의 일시적인 문제로 인한 워크플로우 중단을 최소화하는 데 효과적입니다.

### Insight
'Service unavailable'과 같은 오류는 외부 서비스의 일시적인 문제이므로, n8n의 'Retry On Fail' 기능을 통해 워크플로우의 견고성(Resilience)을 크게 향상시킬 수 있습니다. 특히 AI 서비스는 부하에 따라 응답 시간이 길어지거나 일시적으로 연결이 끊어질 수 있어 재시도 로직이 필수적입니다.

'Exponential Backoff' 전략은 재시도 간격을 점진적으로 늘려 서비스에 대한 요청 부담을 줄이고, 서비스가 정상 상태로 회복할 충분한 시간을 제공합니다. 이는 불필요한 재시도로 인한 추가적인 서비스 장애를 예방하는 모범 사례입니다. 또한, 'Max Retries'를 너무 높게 설정하면 무한 루프에 빠지거나 불필요한 리소스 낭비가 발생할 수 있으므로, 해당 서비스의 특성과 예상되는 오류 패턴을 고려하여 적절한 값을 설정하는 것이 중요합니다. 만약 재시도 후에도 오류가 지속된다면, AI 서비스 제공자의 상태 페이지를 확인하여 광범위한 장애가 있는지 파악해야 합니다.
