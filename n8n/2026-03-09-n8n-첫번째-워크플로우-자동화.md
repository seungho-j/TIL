### Context
사용자는 n8n을 활용하여 첫 번째 워크플로우 자동화를 성공적으로 구축했습니다. 이 워크플로우는 디스코드 메시지 수신을 트리거로 하여, 해당 메시지를 TIL(Today I Learned) 형식으로 변환하고, 변환된 문서를 GitHub 저장소에 푸시하며, 최종적으로 GitHub `README.md` 파일을 업데이트하고 완료 메시지를 발신하는 일련의 과정을 자동화합니다.

### Core
n8n 워크플로우는 다음과 같은 주요 노드들로 구성될 수 있습니다.

*   **Discord Trigger 노드**: 특정 Discord 채널에서 새 메시지가 수신될 때 워크플로우를 시작합니다.
    *   Input: Discord 메시지 이벤트 데이터
    *   Output: 메시지 내용, 발신자 정보 등
*   **Code / Function 노드 (Agent 실행 및 TIL 변환)**: 수신된 Discord 메시지 내용을 기반으로 LLM 에이전트를 실행하여 TIL 형식의 문서로 변환하는 로직을 구현합니다. 이는 외부 LLM 에이전트 호출 또는 내부 스크립트 실행으로 구성될 수 있습니다.
    *   Input: Discord 메시지 내용
    *   Output: TIL 형식의 Markdown 문자열
*   **GitHub 노드 (파일 생성 및 푸시)**: 변환된 TIL 문서를 GitHub 저장소의 지정된 경로(예: `YYYY-MM-DD-제목.md`)에 새로운 파일로 생성하고 푸시합니다.
    *   Input: 파일 경로, 파일 내용 (TIL Markdown)
    *   Output: GitHub API 응답 (커밋 정보 등)
*   **GitHub 노드 (README.md 업데이트)**: 새로 생성된 TIL 문서의 인덱스 링크를 GitHub 저장소의 `README.md` 파일에 추가하여 업데이트합니다.
    *   Input: `README.md` 파일 내용 (기존 내용 + 새 TIL 링크)
    *   Output: GitHub API 응답 (커밋 정보 등)
*   **Discord 노드 (완료 메시지 발신)**: 모든 작업이 성공적으로 완료되었음을 알리는 메시지를 Discord 채널로 전송합니다.
    *   Input: 완료 메시지 텍스트
    *   Output: Discord API 응답

### Insight
n8n으로 워크플로우를 구축하는 과정에서 가장 중요하다고 느낀 점은 각 노드의 입력(Input)과 출력(Output)을 명확히 이해하는 것입니다. 각 노드가 어떤 데이터를 받아 어떤 형태로 다음 노드로 전달하는지 파악하면 복잡한 자동화도 효율적으로 설계할 수 있습니다. 이는 마치 레고 블록을 조립하듯이, 각 블록의 연결 지점만 정확히 알면 전체 구조를 쉽게 만들 수 있는 것과 유사합니다.
