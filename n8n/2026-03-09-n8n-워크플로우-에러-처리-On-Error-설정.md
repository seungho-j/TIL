### Context
n8n 워크플로우 실행 중 'Model output doesn't fit required format To continue the execution when this happens, change the 'On Error' parameter in the root node's settings'와 같은 오류 메시지가 발생하는 경우가 있습니다. 이 오류는 주로 한 노드의 출력이 다음 노드 또는 전체 워크플로우가 기대하는 형식에 맞지 않을 때 발생합니다. 이러한 상황에서 워크플로우의 안정적인 동작을 보장하기 위해 n8n의 'On Error' (에러 발생 시) 파라미터를 설정하는 방법을 이해하는 것이 중요합니다.

### Core
n8n에서 'On Error' 파라미터는 워크플로우 또는 특정 노드에서 오류가 발생했을 때의 동작을 정의합니다. 워크플로우 수준에서 이 설정을 구성하면 전체 워크플로우의 에러 처리 방식을 제어할 수 있습니다.

**워크플로우 'On Error' 파라미터 설정 방법:**
*   n8n 에디터에서 오류가 발생한 워크플로우를 엽니다.
*   워크플로우 캔버스의 빈 공간을 클릭하여 'Workflow Settings' (워크플로우 설정) 패널을 엽니다.
*   'Settings' (설정) 탭에서 'Error Workflow' (에러 워크플로우) 또는 'On Error' 섹션을 찾습니다.
*   'On Error' 드롭다운 메뉴에서 다음 옵션 중 하나를 선택하여 오류 발생 시 워크플로우의 동작을 정의합니다.
    *   **Continue on Error (오류 시 계속 진행)**: 오류가 발생하더라도 워크플로우가 중단되지 않고 다음 노드로 계속 진행됩니다. 이는 특정 오류를 무시하거나 대체 경로로 처리할 때 유용합니다.
    *   **Stop Workflow (워크플로우 중지)**: 오류 발생 즉시 워크플로우 실행을 중지합니다.
    *   **Fail Workflow (워크플로우 실패 처리)**: 워크플로우를 실패 상태로 표시하고 실행을 중지합니다.
    *   **Run Other Workflow (다른 워크플로우 실행)**: 오류 처리 전용으로 설계된 별도의 워크플로우를 트리거하여 오류를 로깅하거나 알림을 보내는 등의 작업을 수행합니다.

**예시 (개념적):**
워크플로우가 외부 API 호출 노드에서 예기치 않은 형식의 응답을 받아 다음 노드가 실패하는 경우, 'On Error'를 'Continue on Error'로 설정하고, 실패한 노드 다음에 오류 처리 로직을 추가하여 문제 있는 데이터를 필터링하거나 기본값으로 대체할 수 있습니다. 예를 들어, 'Set' 노드를 사용하여 기본값을 설정하거나, 'IF' 노드를 사용하여 오류 여부를 확인하고 다른 경로로 데이터를 보낼 수 있습니다.

### Insight
'On Error' 파라미터를 적절히 설정하는 것은 n8n 워크플로우의 복원력(Resilience)을 높이는 데 필수적입니다. 특히 'Model output doesn't fit required format'와 같은 오류는 데이터 유효성 검사(Data Validation) 실패나 스키마 불일치(Schema Mismatch)로 인해 자주 발생합니다. 이 경우 'Continue on Error' 옵션을 사용하여 워크플로우가 완전히 중단되는 것을 방지하고, 오류가 발생한 데이터를 격리하거나 변환하는 추가 노드를 구성하여 전체 프로세스의 안정성을 유지할 수 있습니다.

또한, 중요한 워크플로우의 경우 'Run Other Workflow' 옵션을 활용하여 전용 에러 로깅 및 알림 워크플로우를 구축함으로써, 운영 중 발생하는 문제를 신속하게 인지하고 대응할 수 있는 강력한 에러 관리 시스템을 구축할 수 있습니다. 이러한 에러 처리 전략은 자동화된 시스템의 신뢰성을 크게 향상시킵니다.
